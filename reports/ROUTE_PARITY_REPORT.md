### 2.4 ניתוח שורש הבעיה של השעה (Timezone Bug)
בקובץ [MOTTripPlanningAPIService.swift](file:///c:/Users/DAVID/Code/onebusaway-ios/IsraelMOT/OTPAdapter/MOTTripPlanningAPIService.swift#L44-L48):
```swift
private let isoFormatter: DateFormatter = {
    let formatter = DateFormatter()
    formatter.dateFormat = "yyyy-MM-dd'T'HH:mm:ss.SSS'Z'"
    formatter.timeZone = TimeZone(secondsFromGMT: 0) // <--- כפיית UTC שגויה!
    formatter.locale = Locale(identifier: "en_US_POSIX")
    return formatter
}()
```
כשמשתמש מבקש להגיע בשעה **16:10** בשעון ישראל ב-18 באוקטובר (IDT = UTC+3):
- האפליקציה ממירה את התאריך למחרוזת UTC: `"2026-10-18T13:10:00.000Z"`.
- שרת משרד התחבורה קורא את המחרוזת. במנוע ה-C# (.NET) של משרד התחבורה, שדה ה-DateTime נקרא לעיתים בהנחת שעון חורף ישראלי (+2) או מתעלם מסימול ה-'Z' וממיר בקיזוז מקומי חלקי, ומחשב את היעד כשעה **15:10**!
- כתוצאה מכך, המשתמש ביקש להגיע ב-16:10, אך קיבל מסלולים שמגיעים ב-14:55–15:06.
- **האתר הרשמי לעומת זאת:** באתר הרשמי (`chunk-PCGESSUS.js`) התאריך נשלח כמחרוזת זמן מקומי מלאה (`2026-10-18T16:10:00`) ללא הוספת 'Z' וללא כפיית UTC, וכך השרת מחשב בדיוק לפי השעה המקומית המבוקשת.

הקובץ הגולמי המלא המציג השוואה זו נשמר ב-[reports/raw/compare_1510_1610.json](file:///c:/Users/DAVID/Code/onebusaway-ios/reports/raw/compare_1510_1610.json).
